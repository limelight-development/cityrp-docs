Item Metadata Schema

Item Metadata Schema

This document describes the schema-based item metadata system.

Why this exists

Legacy metadata was stored as opaque strings (for example plate=ABC-123) and parsed manually in many files. That made refactors brittle and made field removal unsafe.

The schema system allows items or bases to declare supported metadata fields and silently ignore removed/unknown fields.

Core APIs

Shared library: core/libraries/sh_itemmeta.lua

  • cityrp.itemmeta.Normalize(itemOrID, rawMeta)
  • cityrp.itemmeta.NormalizeKey(itemOrID, rawMeta)
  • cityrp.itemmeta.Decode(itemOrID, rawMeta)
  • cityrp.itemmeta.GetField(itemOrID, rawMeta, field, default)
  • cityrp.itemmeta.SetField(itemOrID, rawMeta, field, value)
  • cityrp.itemmeta.RemoveField(itemOrID, rawMeta, field)
  • cityrp.itemmeta.NewContext(itemOrID, rawMeta)
  • cityrp.itemmeta.Commit(ply, itemID, amount, oldMeta, context)
  • cityrp.itemmeta.FormatName(itemOrID, baseName, rawMeta)
  • cityrp.itemmeta.FormatDetails(itemOrID, rawMeta)
  • cityrp.itemmeta.NormalizeDisplayKey(itemOrID, rawMeta)
  • cityrp.itemmeta.GetMatchingStacks(itemOrID, stacks, inputMeta)
  • cityrp.itemmeta.ResolveInventoryKey(itemOrID, stacks, inputMeta)

Item hooks receive (..., meta, metaContext) — raw meta string first, then the mutable context. Dirty context is committed automatically from onUse when the item is kept (return false) and from onGive before the inventory transfer. Paths that remove the item (destroy/sell/drop/place) do not commit because the stack is leaving inventory.

Declaring schema on items

Use item metatable helpers:

  • ITEM:SetMetaSchema(schema)
  • ITEM:AddMetaField(name, definition)
  • ITEM:RemoveMetaField(name)
  • ITEM:SetMetaFieldOrder(order)
  • ITEM:MetaContext(meta)

Schema shape:

:SetMetaSchema({
	fields = {
		plate = {
			type = "string",
			label = "Plate"
		},
		turbo = {
			type = "boolean",
			title = false
		}
	},
	order = {"plate", "turbo"}
})

Fields are optional by default: a missing value is omitted unless default is set.

Hidden fields

Mark field definitions with hidden = true to keep them in the storage/stacking key while excluding them from F1 names, F1 detail text, and display-key grouping:

appearance = {
	type = "string",
	hidden = true
}

Storage still uses the full canonical key (NormalizeKey). UI and fuzzy matching use the visible subset (NormalizeDisplayKey).

Title vs details

Mark a field with title = false to keep it in F1 details / display keys while omitting it from the short inventory title:

springs = {
	type = "number",
	label = "Springs",
	title = false
}

Example with base_vehicle (plate in title, springs/turbo details-only):

  • title: 2013 Government Taurus (TEST)
  • details: Plate: TEST, Springs: 3, Turbo: On

Fuzzy inventory matching

GetMatchingStacks and ResolveInventoryKey support:

  • exact canonical keys
  • legacy raw keys before normalization
  • partial visible-field matches (for example plate=ABC-123)
  • bare values for single visible-field items (for example ABC-123 on license plates)

When multiple hidden variants share the same visible metadata, binds that only specify visible fields resolve to the first stack for single-quantity use/pickup/remove commands. Multi-quantity or trade commands require a specific stack or the F1 menu.

Testing metadata (including multi-field)

/giveitem accepts a meta: argument immediately after the amount. Multiple fields are separated with ; (also & / |):

/giveitem <player> Policecar 1 meta:plate=TEST;springs=3;turbo=1 testing multi meta
/giveitem <player> license_plate 1 meta:plate=ABC123 testing plate item

base_vehicle already declares plate, springs, and turbo, so any vehicle item is a convenient multi-meta test target. After giving, F1 should show:

  • title: 2013 Government Taurus (TEST) (springs/turbo use title = false)
  • details line: Plate: TEST, Springs: 3, Turbo: On

Boolean fields accept 1 / 0 / true / false. Do not put spaces inside the meta: token (argument parsing splits on spaces).

Silent field removal

Mark field definitions with removed = true (or use ITEM:RemoveMetaField("field")).

When metadata is normalized:

  • removed fields are dropped silently
  • unknown fields are dropped silently for schema-based items
  • invalid values are dropped silently (or clamped when min/max is set)

Migration file

Inventory meta is normalized by migration 0006_normalize_item_meta_schema:

  • empty/NULL meta values become the canonical empty key "0"
  • stacks that would collide on (steamid, item, meta) after that rewrite are merged (quantities summed) before the update
  • plate values are left unchanged — spaces in plates are intentional (e.g. BAD C0P ≠ BADC0P)

It runs automatically via the migrations runner (core/libraries/sv_migrations.lua).
