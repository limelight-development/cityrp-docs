Modern APIs

Modern APIs

CityRP is a mature codebase containing many legacy patterns and deprecated systems. The table below is the authoritative, up-to-date list of which API to use for each category. Legacy alternatives remain in the codebase — because they predate the migration, not because they're still correct — and must not be used in new or refactored code.

Agents also see a condensed always-on copy of this table in .cursor/rules/agent-musts.mdc. When you add or change a row here, update that MUST card in the same change. The checklist and CI reject criteria for forbidden patterns are in Coding Standards.

Category ✅ Modern API (MANDATORY) ❌ Legacy / Standard GMod (FORBIDDEN) Why?
Audit Logging (player/admin actions, transactions) cityrp.logs.add(nick, steamid, ...) print()<br>ServerLog() Logs to database and admin interfaces for moderation/audit; print is invisible to admins.
Diagnostic Logging (developer debugging, traces) cityrp.logging.GetLogger(namespace):Debug/Info/Error(...) print()<br>ServerLog() Namespaced, level-filterable developer diagnostics. Does not replace cityrp.logs.add() for audit events. See logging.md.
Items ITEM:New("base_id") (Fluent), or ITEM:New() for no base cityrp.item.register({}) Metatable-based fluent API with better inheritance and cleaner code, and it doesn't require a spawnable/purchasable base item to be registered just to be inherited from. See items.md.
Networking See tiers below umsg.*, SendLua(), BroadcastLua() (banned) Pick the highest tier that fits; never use the banned tier.
Color Constants COL_WHITE, COL_BLACK, COL_RED, COL_GREEN, COL_BLUE, COL_GREY (from sh_enumerations.lua) color_white, color_black (GMod globals) Consistency, easier global theming later, reduces reliance on GMod globals. Custom one-off colors are still fine as inline Color(...) calls.
Running a CityRP command from code ply:ConCommand("cityrp <cmd> <args>") (clientside UI)<br>cityrp.command.consoleCommand(ply, cmd, argsTable) (serverside) ply:ConCommand("say /<cmd> <args>") Both end up in cityrp.command.consoleCommand; say / only adds the chat pipeline in front of it, where a PlayerSay hook can swallow the message, cityrp.replacecodes rewrites %/$q codes inside the arguments, >452 characters are dropped silently, and the arguments are re-quoted by a naive scanner. See AGENTS.md footgun #13.
Console Entity CONSOLE console (lowercase) console is a deprecated alias kept only for backwards compatibility with external plugins — see admin/sv_init.lua.
Player chat commands (/ prefix; aka normal / slash-commands) cityrp.command.add(name, access, minArgs, callback, category, syntax, tip[, emgr]) Raw PlayerSay / concommand parsers for gamemode commands; staff tools registered as / Non-privileged player RP/job tools only — generally available to all players. Always pass category (key from categoryAliases), syntax ("<none>" if none; shown on invalid-syntax errors), and a short tip description for the F1 commands menu. Callback is (ply, arguments) table. See commands.md and AGENTS.md footgun #14.
Staff chat commands (! prefix; aka privileged / admin / staff commands) cityrp.acommands.AddCommand(name, func, minArgs, access, emgr, category, syntax, tip) Staff tools on / (even with a restricted access flag); ad-hoc PlayerSay handlers for ! Always use this if the command requires staff privileges of any kind — including RP Assistant. Same mandatory category/syntax/tip metadata as player commands. Callback is (ply, ...) varargs. When moving a staff tool from / to !, leave cityrp.command.redirectToAcommand(oldName) so /old only notifies to use !old. Prefer cityrp.player.resolveTarget and cityrp.command.parseMoney over copy-pasted lookup/money parsing. See commands.md and AGENTS.md footgun #14.
UI Scaling (Derma panels, entity menus, HUD overlays, custom Paint) cityrp.ui.Scale(), cityrp.ui.GetScaleFactor(), cityrp.ui.CreateScaledFont(), cityrp.ui.OnScaleChanged() Ad-hoc ScrW() / 1920 scaling; calling LimelightHUD.GetScaleFactor() directly; fixed surface.CreateFont sizes; hardcoded pixel dimensions that never rebuild on scale change One resolution- and preference-aware scale for all UI; fonts and layout stay in sync when cl_llhud_scale or screen size changes. See ui-scaling.md and AGENTS.md footgun #15.

If existing code conflicts with this table, follow this table — usage of a legacy pattern elsewhere in the codebase is not evidence it's the correct approach, only that it predates this list.

Networking tiers

Networking isn't a simple modern/legacy split — use the highest tier that fits the use case, don't default to a lower one out of habit.

  1. Top tier: Entity Networking (DTVars). Entity:NetworkVar(...) / DataTables (SetupDataTables). Use for anything that's naturally a property of a Lua-authored entity (a SENT or SWEP you define yourself) — it's predicted, delta-compressed, and needs no manual send/receive code. This does not work for GMod's engine-defined vehicle base classes (prop_vehicle_jeep, prop_vehicle_prisoner_pod, etc.) — they don't run SetupDataTables the way a Lua SENT does, so DTVars aren't an option for vehicle state. See tier 3.
  2. Standard networking. For events/actions, use net.* directly. For player state that isn't a natural entity property:
    • ply:SetNSVar(name, value) / ply:GetNSVar(name, default) — for state every client needs to know about that player (broadcast to all clients via net.Broadcast()).
    • cityrp.player.setLocalPlayerVariable(ply, CLASS_TYPE, "_Name", value) — for state only the owning client needs (sent privately via net.Send(ply)).
    • Both require the variable name to be pre-registered (see networking/sh_init.lua) — setting an unregistered name fails silently, with only a print() to console, not an error. Register the name first.
    • Both are Player-metatable-only (FindMetaTable("Player")) — they don't generalize to vehicles or other non-player entities. For non-player entity state where DTVars isn't available (see tier 1), use net.* directly.
  3. Avoided: low-tier networking. SetNWInt/SetNW2Int/etc. (NW/NW2 vars). Avoid for player data — don't use it in new or refactored code, see problems/03 and improvements/01. Exception: vehicles currently use this tier for real (sv_vehicle.lua's locked/engine_on/HP state) precisely because neither tier 1 (DTVars — engine entity, no SetupDataTables) nor tier 2 (NSVar/LocalPlayerVar — Player-only) apply to them. Until a proper net.*-based vehicle-state system exists, this is the practically justified option for vehicles, not just legacy inertia.
  4. Banned. umsg.* (pre-net legacy usermessage library — no structure or size guarantees net provides), SendLua(), BroadcastLua() (execute arbitrary Lua source on the client — a code-injection vector if the string is ever built from anything less than a fully trusted, static literal, and pure legacy debt even when it isn't). Never use these.
