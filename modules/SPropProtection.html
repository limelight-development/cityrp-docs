SPropProtection.RelinkOwnerObjSource ☍

Re-points OwnerObj (a direct Entity reference) at ply's new Player object for every entity ply still owns by OwnerSID. OwnerObj goes stale across a disconnect/reconnect

  • the old Player object was removed on disconnect, so it becomes an invalid entity reference - even though OwnerSID/Owner stay correct the whole time. CPPIGetOwner and several first-party consumers (sh_contextmenu.lua, sv_access.lua, propsave, etc.) read OwnerObj directly, so without this they'd treat a rejoined player's props as unowned.

Parameters:

  • ply Player The reconnecting player.

SPropProtection.KVcantouchSource ☍

Modification allowing mappers to add keyvalues to entites that will override settings of spp so setting spp_canuse to 2 in some entity would make it possible for everyone to use it.

Author: Sebi Keyed by Entity (weak keys, so entries are dropped once the entity is garbage-collected) rather than EntIndex - EntIndex gets reused after an entity is removed, which would otherwise leak a stale override onto whatever unrelated entity spawns at that index next.
