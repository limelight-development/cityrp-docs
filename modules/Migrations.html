Migrations

Database schema migrations runner. Runs ordered SQL migrations against DB_MAIN exactly once per database, tracked via a schema_migrations table created on demand. Migration files live in gamemode/core/migrations/, named NNNN_description.lua, each returning a table with up(done) and down(done) functions.

Ensure the schema_migrations tracking table exists.

Parameters:

  • cb fun(ok: boolean)? Called once the table has been created (or already existed).

Load all migration files from core/migrations, keyed by id.

Migrations.RedoSource ☍

Down then up a single migration id (or the latest applied id if omitted).

Parameters:

  • id number? Migration id to redo; defaults to the latest applied id.
  • cb fun(ok: boolean)? Called with the overall result.
Migrations.RunDownSource ☍

Revert the last count applied migrations (default 1), most-recent first. Each migration's down(done) callback must call done(ok) itself; a failed revert stops the run and leaves its schema_migrations row in place.

Parameters:

  • count number? How many migrations to revert. Defaults to 1.
  • cb fun(ok: boolean)? Called with the overall result.
Migrations.RunPendingSource ☍

Run all pending migrations in ascending id order. Each migration's up(done) callback must call done(ok) itself; a migration that fails is not recorded as applied and stops the run.

Parameters:

  • cb fun(ok: boolean, didApplyAny: boolean) Called with the overall result.
Migrations.RunSequenceSource ☍

Run a sequence of raw SQL statements in order. Stops on the first failed statement and does not call done(true).

Parameters:

  • queries string[] Array of SQL strings.
  • done fun(ok: boolean) Called with the result. Legacy callers that ignore the argument still work when ok is true.
Migrations.StatusSource ☍

Get a status snapshot of applied and pending migrations.

Parameters:

  • cb fun(status: table) Called with {applied = {...}, pending = {...}}, or {applied = {}, pending = {}, error = true} on read failure.
