    cityrp.network

    Clientside receiving, handshake and pull-on-visible resync for the CityRP networking library. Storing values directly on the entity (sh_store.lua) retires the plugin this library replaces' worst clientside bug for free: PLUGIN.NSVars[entIndex], keyed by raw index, was never cleared on disconnect, so a recycled edict inherited whatever the previous occupant left behind. GMod hands a newly-created entity a fresh Lua table regardless of which index it reuses, so ent.__netvars simply does not exist yet for it -- there is nothing to clean up, and nothing here needs to try.

    The one real gap that storage model leaves is timing: a value can arrive (via Update or Resync) referencing an entity this client hasn't networked yet. Those are buffered by raw index in pending until OnEntityCreated actually produces the entity, and swept on a TTL in case it never does (e.g. the entity never entered this client's PVS at all).

    Servercityrp.network.DrainResyncQueues()Source ☍

    Drains every player's resync queue, round-robin, within the configured per-frame budgets. The cursor persists across frames (drainCursorPly) so a player who was last in line this frame is first in line next frame -- with enough players queued to exceed the per-frame budget, this is what guarantees everyone is eventually served instead of the same players always winning the race. If the previous cursor's queue emptied out between frames, the round-robin simply restarts from the first candidate rather than trying to preserve a "position" a table with unstable iteration order can't actually promise -- a minor, self-correcting fairness wrinkle.

    Sharedcityrp.network.GenerateAccessor(netvar)Source ☍

    Defines Get<Name>() (both realms) and Set<Name>() for a var registered with :Accessor(name), on the metatable ACCESSOR_METATABLE maps its scope to (Entity for Global/Entity scope, Player for Player/LocalPlayer, Vehicle/Weapon for those). A no-op for a var with no accessor name set. Idempotent -- safe to call more than once for the same var.

    Set<Name>() is server-only -- setting is server-authoritative -- UNLESS :Predictable() was also called, in which case the client gets its own Set<Name>() too: a purely local apply (ApplyValue with predicted = true, storage + hook only, never a network send) rather than the server's SetNetVar/SetGlobal, which don't exist on the client realm at all (sv_send.lua is server-only). :Predictable() only makes sense for :SetLocalPlayer(), so a scope mismatch here is a logged error, not a silently-generated footgun.

    Parameters

    • netvarNetVarThe var to generate accessors for.

    Servercityrp.network.GetQueue(ply) → table<Entity, boolean>Source ☍

    Gets (creating if needed) a player's resync queue. A queue is a plain weak-keyed set of entities, not an ordered array. Photon's original resync queue is an array plus a drain cursor needing periodic "backlog reclamation" to stop the backing array growing forever; a weak-keyed set has no backing array to grow, and dropping an entity from it is an ordinary key removal. The trade-off is that iteration order (pairs) is unspecified rather than FIFO, which is fine -- fairness across players already comes from the round-robin in DrainResyncQueues, not per-player ordering.

    Parameters

    • plyPlayerThe player metatable, with CityRP's own additions to Garry's Mod's Player.

    Returns

    1. table<Entity, boolean>

    Servercityrp.network.PassesRecipientCheck(netvar, ent, value, ply) → booleanSource ☍

    Whether ply should receive this var's current value, for resync and bootstrap purposes. PVS/PAS are treated as bandwidth filters, not secrecy boundaries: they always pass here, because resync/bootstrap only ever consider a var for a player who is (or is about to be) in a position to receive it anyway.     SharedNetVar:Enum(list) → NetVarSource ☍

    Declares this var as an enum over list, a sequential (ipairs-ordered) array of its legal values. Picks between two wire strategies by comparing their actual bit cost:

    • Direct value (batchable): list is entirely integers. The value itself goes on the wire, sized to its min/max via :Integer/:UInteger -- signed only if min is negative. No offset from min is applied even when every value shares a large common magnitude (e.g. {100,101}) -- an offset would itself need a CODEC_CUSTOM closure, exactly the cost this path avoids.
    • Mapped index (not batchable): the value's index in list goes on the wire instead, via an auto-generated :Write()/:Read() pair sized to #list. Cheaper for a small set of large-magnitude or widely-spread values, at the cost of CODEC_CUSTOM -- never sharing a resync message with sibling vars on the same entity.

    For an all-integer list, the mapped index is used only if it beats the direct-value encoding by more than RESYNC_GROUP_OVERHEAD_BITS. A list containing anything non-integer always uses the mapped index; there is no numeric value to size a direct encoding from.

    Either way, Setting a value not present in list is rejected -- logged, not stored/sent -- by ApplyValue's validate check. nil (clearing the var) always bypasses this check.
